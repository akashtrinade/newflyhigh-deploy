# 🔄 3. HOW IT WORKS PAGE

## What This Page Does
A dedicated page that explains the entire process from start to finish in simple, visual steps.

---

## The Step-by-Step Journey

```
Step 1          →     Step 2          →     Step 3          →     Step 4
┌──────────┐         ┌──────────┐         ┌──────────┐         ┌──────────┐
│  SIGN UP  │   →    │  FIND AN  │   →    │  BOOK A   │   →    │ GET ADVICE│
│  Create   │        │  EXPERT   │        │  SESSION  │        │   & PAY   │
│  Account  │        │  Browse   │        │  Start     │        │   Only for │
│  Free!    │        │  & Filter │        │  Video Call│        │  Time Used │
└──────────┘         └──────────┘         └──────────┘         └──────────┘
```

### Step 1: Create Your Account
- Choose your role: **Client** (seeking advice) or **Expert** (giving advice)
- Enter your name, email, and password
- Verify your email with a one-time code (OTP)
- **For Experts:** Complete your professional profile (skills, experience, hourly rate)

### Step 2: Find the Right Expert
- Browse by category (Business, Tech, Health, Finance, etc.)
- Filter by price, experience, language, country, and availability
- Read reviews and ratings from past clients
- View full expert profiles with bios and credentials

### Step 3: Start a Video Session
- Click "Call Now" on an expert's profile
- Expert receives the call request instantly
- Expert can **Accept** or **Decline** the call
- If accepted, the video call starts with a **FREE 5-minute trial**

### Step 4: Get Advice & Pay for What You Use
- During the free trial, the expert recommends how much time you'll need
- You pay only for the time you use
- After the session, rate your experience
- Expert gets paid (minus platform commission)

# 💰 4. PRICING PAGE

## What This Page Does
Explains how pricing works on FlyHigh — transparent, pay-as-you-go model.

---

## Pricing Model

### For Clients (People Seeking Advice)
- **No subscription fee** — you only pay when you have a session
- **FREE 5-minute trial** on every first call with a new expert
- **Pay per minute** — each expert sets their own hourly rate
- **Example rates:**
  - Junior consultants: ~$15-30/hour
  - Mid-level experts: ~$30-70/hour
  - Senior specialists: ~$70-150/hour
- **No hidden fees** — you see the total before you pay
- **Extend anytime** — if you need more time, you can purchase an extension during the call

### For Experts (People Giving Advice)
- **You set your own rate** — complete control over your pricing
- **Platform commission: 20%** — FlyHigh keeps 20% of what you earn
- **You keep 80%** — of every session payment
- **Example:** If you charge $100/hour and do a 30-minute session:
  - Client pays: $50
  - Platform fee (20%): $10
  - **You earn: $40**
- **No upfront costs** — free to join and list your services

---

## Edge Cases Handled
| Scenario | What Happens |
|----------|--------------|
| Expert changes their rate | New rate applies to future sessions only |
| Client can't afford the rate | They can filter by price range to find affordable experts |
| Currency differences | Platform supports INR (India); configurable to other currencies |
| Refund scenario | Payment is held until session completes; disputes handled by support |

# 🔐 6. AUTHENTICATION — SIGN UP

## What This Feature Does
Allows new users to create an account securely. Uses **email OTP verification** to ensure only real people can sign up.

---

## The Sign Up Flow (Step by Step)

```
┌─────────┐     ┌──────────┐     ┌───────────┐     ┌────────────┐     ┌──────────┐
│ Enter    │     │  OTP is   │     │  Enter OTP │     │  Account    │     │ Redirect │
│ Details  │ ──► │  Sent to  │ ──► │  from      │ ──► │  Created    │ ──► │ to       │
│ & Submit │     │  Email    │     │  Email     │     │  Success!   │     │ Dashboard│
└─────────┘     └──────────┘     └───────────┘     └────────────┘     └──────────┘
```

### Step 1: Fill in Your Details
- First Name & Last Name
- Email address
- Password (must meet security requirements)
- Choose Role: **Client** or **Expert**
- Agree to Terms & Conditions

### Step 2: Email Verification (OTP)
- A 6-digit code is sent to the provided email
- The OTP is valid for **10 minutes**
- You can request a **new OTP up to 3 times per hour** (rate limit)

### Step 3: Enter the OTP
- Type the 6-digit code on the verification screen
- If correct → Account is created and you can log in
- If incorrect → You can try again (the OTP remains the same until it expires)

---

## Important Details

### What is a "Pending User"?
When you first sign up, your data is stored as a "pending" (temporary) account. Only after OTP verification does it become a real account. This prevents fake accounts.

### Rate Limiting
- Maximum **3 OTP requests per hour** per email address
- If exceeded: "Too many OTP requests. Please try again later."
- After 1 hour, the limit resets automatically

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Email already registered | "Email already registered. Please log in." |
| OTP expired (after 10 min) | Pending account is deleted; user must sign up again |
| Wrong OTP entered | "Invalid OTP. Please try again." — user can retry |
| OTP requested too many times | Blocked for 1 hour with a clear message |
| User leaves mid-signup, comes back | Can resume — new OTP is sent to the same email |
| Google Sign-Up (no password) | Special handling: password field is left empty; Google ID is stored instead |
| Weak password | Rejected with guidance on password requirements |

# 🔐 7. AUTHENTICATION — LOGIN

## What This Feature Does
Allows existing users to sign into their account and access their dashboard.

---

## The Login Flow

```
┌──────────┐     ┌──────────────┐     ┌────────────────┐
│ Enter     │     │  Verify       │     │  Redirect to    │
│ Email &   │ ──► │  Password     │ ──► │  Your Dashboard  │
│ Password  │     │  Against DB   │     │  (Role-Based)   │
└──────────┘     └──────────────┘     └────────────────┘
```

### What Happens Behind the Scenes
1. User enters email + password
2. System checks if the email exists
3. Password is verified (using secure encryption — never stored as plain text)
4. If correct, two secure tokens (Access Token + Refresh Token) are created
5. These tokens are stored as secure browser cookies (not accessible to JavaScript — protection against hackers)
6. User is redirected to the correct dashboard based on their role

### Role-Based Redirect
| User Role | Profile Completed? | Redirect To |
|-----------|-------------------|-------------|
| CLIENT | Yes/No | `/client-dashboard` |
| EXPERT | Yes | `/expert-dashboard` |
| EXPERT | No | `/expert/profile` (profile completion) |
| ADMIN | N/A | `/admin-dashboard` |

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Wrong email or password | "Invalid email or password" — does NOT reveal which one is wrong (security best practice) |
| Account deactivated by admin | "Account is deactivated. Please contact support." |
| Expert logs in | Automatically marked as "Online" for clients to see |
| Tokens expire | Refresh token automatically gets new tokens without re-login |
| Already logged in on another device | Works fine — multiple sessions are allowed |
| Browser cookies disabled | Login may not persist — user is informed |

# 🔐 8. AUTHENTICATION — FORGOT PASSWORD

## What This Feature Does
Allows users who forgot their password to reset it securely using email OTP verification.

---

## The 3-Step Reset Flow

```
Step 1                Step 2                Step 3
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ Enter Email   │     │ Enter OTP    │     │ Set New       │
│ → Receive OTP │ ──► │ → Verify     │ ──► │ Password      │
│   via Email   │     │   Code       │     │ → Done!       │
└──────────────┘     └──────────────┘     └──────────────┘
```

### Step 1: Request Password Reset
- User enters their registered email
- System sends a 6-digit OTP to that email
- **Security note:** The message always says "If an account exists, an OTP has been sent" — this prevents attackers from discovering which emails are registered

### Step 2: Verify OTP
- User enters the code they received
- Valid for **10 minutes**
- Rate limited: **3 requests per hour**

### Step 3: Set New Password
- User enters a new password (with the OTP again for final verification)
- Password is updated securely (encrypted)
- OTP record is deleted (single-use — cannot be reused)
- User can now log in with the new password

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Email not registered | Same success message — doesn't reveal if account exists (privacy) |
| OTP expired | "OTP has expired. Please request a new one." |
| Wrong OTP entered | "Invalid OTP. Please try again." |
| Too many OTP requests | Rate limited: "Too many requests. Try again later." |
| User tries to reuse old OTP | OTP deleted after successful reset — cannot be reused |

# 🔐 9. AUTHENTICATION — GOOGLE LOGIN

## What This Feature Does
Allows users to sign up and log in using their Google account — faster than filling out forms.

---

## How It Works

```
┌──────────────┐     ┌────────────────┐     ┌──────────────┐
│ Click "Sign   │     │ Google Shows    │     │ FlyHigh       │
│ in with       │ ──► │ Consent Screen  │ ──► │ Creates/      │
│ Google"       │     │ (One-time)      │     │ Logs In User  │
└──────────────┘     └────────────────┘     └──────────────┘
```

1. User clicks "Continue with Google"
2. Google opens a popup asking: "FlyHigh wants to access your name and email. Allow?"
3. User approves
4. FlyHigh receives the user's name and email from Google
5. If this is a new user → a pending account is created (still needs OTP verification for security)
6. If returning user → logged in immediately

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Google popup blocked by browser | User is prompted to allow popups |
| Google auth fails | Error message displayed; user can try email signup instead |
| Same email used for both Google and email signup | System detects this and links the accounts |
| User revokes Google access later | Can still log in with email + password if they set one |

### How Status Is Determined

1. **OFFLINE** → **ONLINE:** Happens automatically when the expert logs in
2. **ONLINE** → **BUSY:** Happens automatically when the expert accepts a call
3. **BUSY** → **ONLINE:** Happens automatically when the call ends
4. **ONLINE** → **OFFLINE:** Happens automatically when the expert logs out

### Heartbeat System
- The expert's browser sends a "heartbeat" signal every few seconds
- If the heartbeat stops for more than **2 minutes** (e.g., browser closed, internet lost), the expert is automatically marked as OFFLINE
- This prevents clients from calling experts who have left

| Expert forgets to set availability | Logging in = automatically online |

# 💳 23. PAYMENT FLOW

## What This Feature Does
Handles all money transactions — creating payment orders, verifying payments, and processing extensions.

---

## Payment Architecture
FlyHigh uses **Razorpay** — a secure payment gateway — to handle all transactions. FlyHigh never stores your credit card or bank details.

---

## Payment Scenarios

### Scenario A: Initial Payment (First Time Purchase)

```
Step 1: Expert recommends duration
        (e.g., "30 minutes needed")
              │
Step 2: System calculates price
        Rate: $100/hr × 30 min = $50.00
              │
Step 3: Razorpay order created
        (Order ID, Amount, Currency)
              │
Step 4: Payment popup opens
        Client enters card/UPI details
              │
Step 5: Payment captured by Razorpay
        Razorpay sends: Payment ID + Signature
              │
Step 6: FlyHigh VERIFIES the signature
        HMAC-SHA256 cryptographic check
        (Ensures payment is genuine, not fake)
              │
Step 7: Session activated!
        - Status → PAID_SESSION
        - Countdown timer starts
        - Payment record saved
```

### Scenario B: Session Extension (Need More Time)

```
During paid session, < 5 min remaining
              │
"Extend Session?" prompt appears
              │
Client clicks "Extend" → selects more time
              │
New payment order created (type: EXTENSION)
              │
Payment processed (same secure flow)
              │
Timer EXTENDED by purchased minutes
              │
New payment record created (linked to same session)
```

---

## Payment Security

### Signature Verification (How We Prevent Fraud)
1. Razorpay sends three things: Order ID, Payment ID, and a **Signature**
2. FlyHigh calculates its own signature using the secret key
3. If both signatures match → payment is genuine ✅
4. If they don't match → payment rejected as fraudulent ❌

This ensures:
- Nobody can fake a payment confirmation
- Only genuine Razorpay payments are accepted
- Both client and expert are protected

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Client's card is declined | Payment popup shows bank error; session stays in free trial |
| Payment succeeds but signature verification fails | Payment rejected; system logs error for investigation |
| Client tries to pay twice for same session | Duplicate detection: already-paid sessions skip re-processing |
| Network drops during payment | Client can retry; if payment went through, Razorpay handles it |
| Extension when session already expired | "Extension requires an active paid session" error |
| Expert changes rate during session | Rate is SNAPSHOTTED (locked) at session start; changes don't affect |
| Client disputes a charge | Payment status tracks everything; support can investigate |
| Razorpay service is down | "Payment gateway error" shown; client can try again later |

# 🔒 25. SECURITY & PRIVACY

## What This Module Does
Protects user data, prevents unauthorized access, and ensures the platform is safe for everyone.

---

## Security Features

### 🔐 Authentication Security
- **JWT (JSON Web Tokens):** Secure, tamper-proof tokens stored in httpOnly cookies
- **httpOnly Cookies:** Cannot be read by JavaScript — protects against XSS attacks (hackers stealing tokens via malicious scripts)
- **Secure Cookies:** Only sent over HTTPS (encrypted connection)
- **Token Expiry:** Access tokens expire; refresh tokens allow seamless renewal
- **BCrypt Password Hashing (strength 12):** Passwords are never stored — only mathematical hashes. Even if the database is breached, passwords cannot be recovered

### 🛡️ Rate Limiting (Abuse Prevention)
- Login attempts: Limited per IP address
- OTP requests: **3 per hour per email**
- API calls: Limited to prevent server overload
- If limit exceeded: Request blocked with a clear message

### 🚪 Role-Based Access Control
- **CLIENT** users can only access client pages
- **EXPERT** users can only access expert pages
- **Unauthenticated** users can only see public pages
- Server verifies role on EVERY request — not just at login

### 🔑 Payment Security
- Razorpay handles all card/bank details — FlyHigh never sees them
- Payment signatures cryptographically verified (HMAC-SHA256)
- Duplicate payment detection prevents double-charging

### 📧 Email Verification
- OTP required before account activation
- Prevents fake accounts and spam registrations

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Expired token | 401 Unauthorized → frontend redirects to login |
| Wrong role accessing page | 403 Forbidden → blocked |
| Brute force login attempt | Rate limiter blocks after threshold |
| Token stolen (theoretical) | httpOnly + Secure + short expiry minimizes risk |
| Session hijacking attempt | CORS policy + JWT validation prevents cross-site requests |

# 🌐 26. REAL-TIME COMMUNICATION

## What This Module Does
Enables instant, real-time communication between clients and experts — call notifications, video/audio streaming, and chat.

---

## Two Communication Systems

### 1. WebSocket (Socket.IO) — Signaling Server
**What it does:** Sends instant notifications and coordinates video calls

| Event | Direction | What Happens |
|-------|-----------|--------------|
| **Call Request** | Client → Server → Expert | Expert gets instant popup: "Client wants to call you" |
| **Call Accepted** | Expert → Server → Client | Client sees: "Expert accepted! Joining call..." |
| **Call Rejected** | Expert → Server → Client | Client sees: "Expert declined: [reason]" |
| **Call Ended** | Either → Server → Other | Other person notified: "Call ended" |
| **Payment Completed** | Server → Both | Both notified: "Payment confirmed" |
| **Session Extended** | Server → Both | Timer updates in real-time |
| **Timer Expired** | Server → Both | Session auto-ends |
| **User Presence** | Server → Clients | Online/offline status updates |

### 2. WebRTC — Video & Audio
**What it does:** Direct peer-to-peer video and audio streaming

- Highest quality: Direct connection between browsers (not through server)
- Low latency: Minimal delay for natural conversation
- Adaptive quality: Adjusts to network conditions
- Secure: End-to-end encrypted

---

## How a Call Connects (Simplified)

```
1. Client clicks "Call Now"
   ↓
2. Signaling Server tells Expert's browser: "Incoming call!"
   ↓
3. Expert clicks "Accept"
   ↓
4. Signaling Server tells both browsers: "Here's how to connect directly"
   (This is called "signaling" — like exchanging phone numbers)
   ↓
5. Both browsers connect DIRECTLY via WebRTC
   (Video/audio flows peer-to-peer, not through our servers)
   ↓
6. Signaling Server stays connected for:
   - Status updates (timer, payments, end call)
   - Fallback if direct connection fails
```

---

## Edge Cases Handled

| Scenario | What Happens |
|----------|--------------|
| Firewall blocks direct connection | WebRTC uses TURN servers as relay (fallback) |
| Signaling server restarts | WebSocket reconnects automatically |
| Client and expert on different continents | WebRTC adapts quality; signaling server coordinates |
| Multiple browser tabs open | Each maintains independent WebSocket connection |
